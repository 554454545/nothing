## 2. 规划前后端分离

### 目标架构

未来可以拆成：

```text
Cloudflare Pages
  └── 前端网页

Cloudflare Workers
  └── 后端 API

Cloudflare D1
  └── 数据库
```

请求关系：

```text
用户访问 Pages
  ↓
前端请求 Workers API
  ↓
Workers 访问 D1
```

示例地址：

```text
前端：https://prism-bloom.pages.dev
后端：https://api.quacker-zhang.workers.dev
```

### 拆分时需要处理

- 将前端网页独立部署到 Cloudflare Pages。
- 将 API 保留在 Cloudflare Workers。
- 将前端的相对请求改为 API 地址配置。
- 为 Workers API 增加 CORS。
- 区分本地、预览和生产环境变量。
- 分开前端和后端的构建与部署命令。
- 重新处理 Cookie、Session 和登录域名。
- 重新确认 SSR、Server Actions 和文件上传的运行方式。
- 保留 D1 作为独立数据库，不改变数据迁移流程。

### 拆分条件

满足以下情况后再拆分：

- 需要多个前端共用同一个 API。
- 前端需要独立发布和回滚。
- 前后端需要独立维护或扩展。
- 当前一体化部署已经影响开发效率。
- 已经掌握同源请求、API、D1 和 Workers 的基本链路。

当前不拆分，先把 Workers 一体化全栈方式跑熟。
